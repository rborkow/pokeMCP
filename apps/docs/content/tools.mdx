# Tools Reference

PokéMCP provides **7 tools**, defined in a single registry (`src/tool-registry.ts`) shared by the
MCP server and the [REST API](/api-reference), across four categories:

1. **Core tools** (bundled Pokémon Showdown data — no network calls): `lookup_pokemon`,
   `validate_moveset`, `validate_team`, `suggest_team_coverage`
2. **Usage statistics** (Cloudflare KV): `get_usage_stats`
3. **Metagame trends** (Cloudflare D1 time series): `get_meta_trends`
4. **Strategy search** (Cloudflare Vectorize + Workers AI, RAG): `query_strategy`

## Core Tools

These four run entirely on Pokémon Showdown data bundled into the Worker at build time — no
Cloudflare bindings, no network calls.

### lookup_pokemon

Get detailed Pokémon information: base stats, types, abilities (including hidden), tier
placement, evolution chain, and generation-specific mechanics (Tera type, Gigantamax, required
items/formes).

**Parameters:**
- `pokemon` (string, required) — Pokémon name
- `generation` (string, optional) — Generation number (e.g., `"9"`)

**Example:**
```json
{
  "pokemon": "Garchomp"
}
```

### validate_moveset

Check whether a Pokémon can legally learn a set of moves, and show the learn method
(level-up, TM/HM, tutor, egg move, etc.) for each legal move.

**Parameters:**
- `pokemon` (string, required)
- `moves` (array of strings, required) — move names to validate
- `generation` (string, optional) — defaults to Gen 9 if omitted

**Example:**
```json
{
  "pokemon": "Garchomp",
  "moves": ["Earthquake", "Dragon Claw", "Swords Dance", "Fire Fang"],
  "generation": "9"
}
```

### validate_team

Validate a full team against format rules. Dispatches on `format`:

- A **Pokémon Champions regulation id** (`champions-regma`, `champions-regmb`) routes through the
  dedicated regulation validator — dynamic legality allow-list, Species/Item Clause, bring-count
  rules, Mega Evolution forms.
- Anything else (e.g. `gen9ou`, `gen9vgc2026regi`) runs through the legacy Showdown-style
  validator — team size (max 6), Species Clause, move/ability legality, Tera type validation
  (Gen 9 only).

**Parameters:**
- `team` (array of objects, required) — each item: `pokemon` (string), `moves` (array of
  strings), `ability` (string, optional), `item` (string, optional), `level` (number, optional)
- `format` (string, optional) — defaults to `"OU"` for the Showdown path if omitted

**Example:**
```json
{
  "team": [
    {
      "pokemon": "Garchomp",
      "moves": ["Earthquake", "Dragon Claw", "Swords Dance", "Fire Fang"],
      "ability": "Rough Skin",
      "item": "Focus Sash"
    },
    {
      "pokemon": "Ferrothorn",
      "moves": ["Stealth Rock", "Spikes", "Power Whip", "Gyro Ball"],
      "ability": "Iron Barbs"
    }
  ],
  "format": "gen9ou"
}
```

### suggest_team_coverage

Analyze a team's type coverage: defensive weaknesses, resistances, type distribution, and
suggested types to fill gaps.

**Parameters:**
- `current_team` (array of strings, required) — Pokémon names on the team
- `format` (string, optional)

**Example:**
```json
{
  "current_team": ["Garchomp", "Ferrothorn", "Rotom-Wash"],
  "format": "gen9ou"
}
```

## get_usage_stats

A single tool covering all Smogon usage-statistics views. The `type` argument selects which view
is returned; `format` defaults to `"gen9ou"` if omitted.

| `type` | Requires `pokemon` | `limit` default | Returns |
|---|---|---|---|
| `popular_sets` | Yes | — | Most-used abilities, items, moves, EV spreads, and (Gen 9) Tera types for one Pokémon |
| `meta_threats` | No | 20 | Top Pokémon in the format ranked by usage % |
| `teammates` | Yes | 10 | Most common teammates for one Pokémon |
| `checks_counters` | Yes | 15 | Pokémon that most reliably beat the target, scored by Smogon's `(win rate − 4×stdev) × 100` rating |
| `metagame` | No | — | Format-wide stats: Pokémon count, total battles, average team weight, usage-tier breakdown |

**Parameters:**
- `type` (enum, required): `popular_sets` \| `meta_threats` \| `teammates` \| `checks_counters` \| `metagame`
- `pokemon` (string, optional — required in practice for `popular_sets`/`teammates`/`checks_counters`)
- `format` (string, optional, default `"gen9ou"`)
- `limit` (number, optional)

**Examples:**
```json
{ "type": "popular_sets", "pokemon": "Garchomp", "format": "gen9ou" }
```
```json
{ "type": "meta_threats", "format": "gen9ou", "limit": 20 }
```
```json
{ "type": "teammates", "pokemon": "Garchomp", "format": "gen9ou" }
```
```json
{ "type": "checks_counters", "pokemon": "Garchomp", "format": "gen9ou" }
```
```json
{ "type": "metagame", "format": "gen9ou" }
```

Champions regulation ids (`champions-regma`, `champions-regmb`) are also accepted for `format` —
they're transparently remapped to the matching `gen9championsvgc2026regm*` Smogon stats file. If
Smogon hasn't published stats for a format yet, the tool returns an explanatory message instead of
an error.

## get_meta_trends

Reads a Cloudflare D1 time series (populated monthly by `scripts/backfill-history.ts` /
`scripts/append-history.ts`) to describe how a metagame changes over time. Tuned for VGC/doubles
and Pokémon Champions, but works for any format with recorded history.

**Parameters:**
- `type` (enum, required): `usage_trend` \| `shifts` \| `momentum` \| `evolution_summary`
- `pokemon` (string, optional — **required** for `usage_trend`)
- `format` (string, optional) — defaults to the newest Pokémon Champions regulation with published
  Smogon stats (auto-advances as new regulations launch; currently `champions-regmb`). Also
  accepts continuous formats like `gen9doublesou`/`gen9ou`, or a past VGC regulation id.
- `from` (string, optional) — start month, `"YYYY-MM"`
- `to` (string, optional) — end month, `"YYYY-MM"` (defaults to the latest snapshot on record)
- `window` (number, optional) — months back from `to`; an alternative to `from`
- `limit` (number, optional) — max rows per list (risers/fallers/etc.)

| `type` | What it does | Default window (if no `from`/`window`) |
|---|---|---|
| `usage_trend` | One Pokémon's usage % and rank across months, with net change and peak | 12 months |
| `shifts` | Risers/fallers (usage delta) and entrants/dropouts (≥2% usage) between two snapshots | 3 months |
| `momentum` | Slope, EWMA, volatility, and acceleration per Pokémon (needs ≥4 snapshots in range) | 6 months |
| `evolution_summary` | Top-10 board, biggest movers, and momentum highlights, narrated together | 6 months |

**Examples:**
```json
{ "type": "usage_trend", "pokemon": "Flutter Mane", "format": "champions-regmb" }
```
```json
{ "type": "shifts", "format": "champions-regmb", "window": 3 }
```
```json
{ "type": "momentum", "format": "gen9vgc2026regi", "limit": 10 }
```
```json
{ "type": "evolution_summary", "format": "gen9doublesou" }
```

If the format has fewer snapshots than a mode needs (e.g. `momentum` needs at least 4 monthly
snapshots), the tool returns a message explaining what's missing rather than an error.

## query_strategy

Semantic (RAG) search over Smogon strategy write-ups, backed by Cloudflare Vectorize + Workers AI
embeddings (`@cf/baai/bge-base-en-v1.5`).

**Parameters:**
- `query` (string, required) — natural-language strategy question
- `pokemon` (string, optional) — filter to a specific Pokémon
- `format` (string, optional)
- `sectionType` (enum, optional): `overview` \| `moveset` \| `counters` \| `teammates`
- `limit` (number, optional)

Passing `pokemon` or `sectionType` switches the tool to a structured-text response (grouped by
match); omitting both returns the raw ranked-results response. Either way the MCP tool returns
plain text. Results below a 0.5 relevance score (after reranking for format/Pokémon match and
recency) are filtered out before being returned.

**Examples:**
```json
{ "query": "How do I counter Kingambit in gen9ou?", "format": "gen9ou" }
```
```json
{
  "query": "best Choice Scarf sets",
  "pokemon": "Garchomp",
  "sectionType": "moveset",
  "format": "gen9ou"
}
```
