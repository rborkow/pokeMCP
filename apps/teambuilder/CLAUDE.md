# Teambuilder App (www.pokemcp.com)

Next.js 16 App Router site deployed to Cloudflare Workers through OpenNext. Despite the directory
name, there is no team builder here any more. The site is:

- **Reports and Pokémon pages** — monthly meta reports and per-Pokémon trend pages, prerendered
  from generated content. This is the SEO surface.
- **Newsroom and event pages** — Champions tournament results read from D1.
- **PokeMCP Prep** — pick an opposing team, get a rule-based battle card, save plans and teams.

The site calls no AI provider. The matchup coach, builder chat, interview and report questions
were removed in November 2026. The product for interactive team building is the VGC Teambuilder
MCP connector served by the worker in `src/` (see the root `CLAUDE.md`).

## Routes

| Route | What it is |
|-------|------------|
| `/` | Newsroom: recent events, latest report. Server-rendered on demand |
| `/events/[slug]` | One event's results and teams, with "Prepare against team" |
| `/prep/new`, `/prep/[id]` | Start a matchup plan; the match desk for a saved plan |
| `/teams` | Saved teams and plans, workspace JSON export |
| `/account` | Optional Discord/Google sign-in, sync, account deletion |
| `/reports`, `/reports/[slug]`, `/reports/[slug]/[month]` | Meta reports (MDX in `src/content/reports/`) |
| `/pokemon/[id]/[format]` | Per-Pokémon trend pages (`src/data/mons/`) |
| `/t/[id]` | Legacy shared-team view. New links can't be created |
| `/privacy` | Privacy policy, covering the site and the connector |
| `/admin` | Analytics dashboard (Cloudflare Access) |
| `/api/prep/generate` | Rule-based battle card (`lib/prep/battle-card.ts`). No model call |
| `/api/prep/sync` | Merge-only workspace sync; `DELETE` removes a user's synced data |
| `/api/prep/analytics` | Counts product events |
| `/api/auth/[...all]` | Better Auth |
| `/api/health` | Liveness only |
| `/mcp`, `/sse`, `/api/mcp`, `/api/tools` | `410` tombstones pointing at `api.pokemcp.com/mcp` |
| `/builder`, `/build` | Redirect to `/` |

Report and Pokémon pages are generated by `scripts/generate-reports.ts` at the repo root and
reach `main` through the monthly review PR. Do not hand-edit generated MDX or JSON.

## Known gap: Prep cannot take a new team

`/prep/new` reads the player's own team from `team-store` ("current builder team") or from saved
snapshots of it. The builder that filled `team-store` no longer exists, so a visitor without a
team saved before July 2026 cannot create a plan. `PrepSetupForm` and `TeamsWorkspace` still link
to the old builder address, which now redirects home. Either add a team import to Prep or retire
Prep — this is an open product decision; do not paper over it.

## Things that will bite you

- **The root `.gitignore` ignores `build/` everywhere.** A route at `src/app/build/` was silently
  never committed, so `/build` returned 404 in production for four months while the sitemap and
  reports linked to it. Negations exist for `src/app/**/build/`; check `git status` after adding
  any directory whose name also appears in that file (`lib`, `dist`, `build`, `env`, …).
- **Saved coach conversations are user data.** The coach is gone, but conversations saved before
  then live in `prep-store` (`coachMessages`), in D1 (`prep_message`) and in workspace exports,
  and `CoachHistory` shows them read-only. Do not change the store shape, persist version,
  `CoachMessageSchema` or the sync payload in a way that drops them.
- **Every environment binds production data.** See the root `CLAUDE.md`.

## Conventions

- **File naming**: `PascalCase.tsx` for components, `camelCase.ts` for utilities
- **Imports**: always the `@/` alias; `import type` for type-only imports
- **Client components**: add `"use client"` to interactive components
- **Classnames**: `cn()` from `@/lib/utils`
- **Icons**: `lucide-react` only
- **Exports**: named exports; default exports only in `page.tsx`
- **Styling**: Tailwind 4. Prep pages use the `prep-*` classes in `globals.css`
  (`prep-shell`, `prep-button-primary`, `prep-text-link`, `prep-field`)
- **Formatting**: Biome. Many existing files are not Biome-formatted — format only the files you
  change, or a small edit turns into hundreds of lines of churn

## Bindings and secrets

`wrangler.toml`: `META_DB` (tournament and usage history), `PREP_DB` (accounts, teams, plans,
coach history), `PREP_RATE_LIMITER`, `ANALYTICS`. Secrets: `BETTER_AUTH_SECRET` and the Discord
and Google OAuth client ids and secrets.

No longer used by any code, pending removal: the `PREP_ANALYSIS` service binding, the two
`AI_RATE_LIMITER_*` bindings, and the `ANTHROPIC_API_KEY`, `CLOUDFLARE_AI_GATEWAY_URL` and
`CF_AIG_TOKEN` secrets.

## Testing

```bash
bun run test:run   # Vitest + React Testing Library + jsdom
bun run ci         # lint, tests, OpenNext bundle, generated-types check, tsc — what CI runs
```

Tests live in `src/__tests__/`. After a change that removes or moves files, serve the build
(`bunx next start`) and request a monthly report page: it is the route most likely to break
without failing a test.
