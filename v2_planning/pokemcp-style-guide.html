POKEMCP · STYLE GUIDE · V1

Design system for the refreshed UI

Built on shadcn/ui with minimal customization. Replaces the current dark-with-yellow-glow aesthetic with a flat, professional system that defaults to dark mode in the app and light mode on the landing page. All color, spacing, and component tokens below can be pasted directly into a shadcn install.

Foundation

Three principles underpin everything. When in doubt, follow them.

01
Flat, not decorated
No gradients, glows, shadows, or textures. A single pixel of border does the work ten pixels of blur used to do.
02
Quiet where the app is loud
Pokémon names, moves, and data are inherently colorful. The chrome around them must not compete. Neutral surfaces, muted text.
03
Monospace is a signal
Used for timestamps, IDs, version numbers, keyboard shortcuts, and technical status — never for running copy. It tells the eye "this is data."

Spacing, radius, and motion

spacing scale4 / 8 / 12 / 16 / 20 / 24 / 32 / 48 / 64 px
radius--radius: 0.5rem (8px) base. Buttons use calc(radius - 2px). Pills use 999px. Avoid intermediate values.
borders1px solid hsl(var(--border)). No 2px borders except for focus states. No dashed borders except in empty-state illustrations.
focus ring2px ring at hsl(var(--ring) / 0.2). Never a thick glow.
motion120–180ms for hover/press. 240ms for layout shifts. Never longer. No elastic/bouncy easing.
shadowsNone by default. Use only for floating elements (tooltip, popover) at 0 4px 12px rgb(0 0 0 / 0.08).

Product patterns

Combinations of the primitives above, specified once so every screen uses them consistently.

Sits at the top of the app and the top of the landing. Entirely monospace, all lowercase or uppercase, slashes as separators. The only "decorative" element anywhere in the system.

Coach message

Coach responses have no bubble — just the avatar and flowing text, with optional inline components (data card, team-diff flag, follow-up chips). User messages use a bubble so the direction of conversation is visible.

Inline data card

The load-bearing element for coach credibility. Always inside a coach message. Two-column layout, label left (muted), value right (foreground), 4px row gap. Values can carry semantic color only when the data itself is negative (low win rate = destructive, open threat = warning).

Quick-action chip row

Sits above the chat input. Contents change based on team state. Outline, small radius, muted text that darkens on hover. These are shortcuts to common messages — semantically identical to typing them — not buttons for distinct actions.

Interview step

Progress bar top-right (green segments for completed, muted for remaining). Previous answers as collapsed chips. Current question with adaptive hint. Answer options as buttons; selected state fills in coach-surface with coach-border.

Voice and copy

Tone follows the visuals. Confident, specific, technical when technical, plain when plain.

PrincipleExample
Sentence case, always "Start the interview" not "Start The Interview" or "START THE INTERVIEW." Only the monospace status bar uses caps.
No brand personas "Coach" not "Professor Kukui." The AI has a role, not a name.
Specific over cute "Swapped Rillaboom → Scizor. Resists Dragon Claw." Not "Done! ✨ Swapped out your grass type for something spicier."
Show reasoning Every coach recommendation names the tradeoff it considered, not just the conclusion. "Skipped Grimmsnarl — too slow without setup" is better than "Here's your team."
Numbers when possible "0/0 Garchomp dies to +1 Bullet Punch" not "Scizor handles Garchomp well." The calc is the authority.
No exclamation marks Enthusiasm undermines the precision signal. If something is good, the data shows it.
No emoji in product UI Emoji are texture. They belong in tournament Twitter posts, not the coach. (Acceptable in social copy and blog content.)
Monospace for data, sans for prose Version numbers, shortcuts, timestamps, move names in calc tables = mono. Coach explanations, feature copy, marketing = sans.

Don'ts

Concrete contrasts with the current UI. These are the patterns to actively retire.

Glowing yellow accent, dashed orange border with ambient glow, heavy weight on "Your Team," video-game aesthetic competes with the tool's own content.
DO · REFRESHED
YOUR TEAM · 0/6
No team yet
Monospace overline instead of loud heading. Dashed border at 1px, no glow. Empty state offers one primary path instead of six identical empty slots.
  • No glows or radial gradients. The current "halo" around selected slots reads as gamified. Use a 1px border color change on selection, nothing else.
  • No yellow/gold as brand accent. It competes with Pokémon type colors and cheapens the professional signal. The only accent color is coach (teal), used exclusively for AI actions.
  • No 2x weight headings. Section labels are small, muted, monospace overlines. Bold 26px "Your Team" belongs in a game UI, not a tool.
  • No placeholder language as call to action. "Add Pokemon · Click to browse" × 6 is anti-onboarding. Empty states should present one primary path, not an empty grid.
  • No Pokéball brand marks in UI chrome. Pokéballs are fun in content (sprites, team illustrations). They're noise in navigation, headers, and logos.
  • No decorative dividers. Gradients, glowing lines, double-rules. A single 1px border at spec color handles every separation need in the system.
  • No toast notifications for positive actions. If the user asked for it and it happened visibly, don't also pop a toast. Only use toasts for off-screen events or errors.

Install & setup

Tailwind extension

Expose the custom tokens as Tailwind colors in tailwind.config.ts.

extend: {
  colors: {
    coach: {
      DEFAULT: "hsl(var(--coach))",
      surface: "hsl(var(--coach-surface))",
      foreground: "hsl(var(--coach-foreground))",
    },
    warning: { DEFAULT: "hsl(var(--warning))", surface: "hsl(var(--warning-surface))" },
    info: { DEFAULT: "hsl(var(--info))", surface: "hsl(var(--info-surface))" },
  },
},

Default mode

App defaults to dark (long sessions, second-screen use during battles). Landing page defaults to light (conversion-oriented, scannable). Both respect prefers-color-scheme and a manual theme toggle in user settings.
